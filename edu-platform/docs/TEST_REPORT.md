## المرحلة الثانية: المعلمون والفيديو

**الدورة الكاملة المطلوبة** — `tests/e2e/05-teacher-cycle.spec.ts` ✅ ناجحة:
المالك ينشئ معلمًا (مواد، نسبة 40%) ← يفعّل حسابه (كلمة مرور تظهر مرة واحدة) ← المعلم يدخل (صفحات المالك 404) وينشئ «شرح وحدة» بسعر مقترح ← يرفع **3 فيديوهات** مباشرة إلى Bunny عبر TUS ← المعالجة ثم Webhook موقّع ← «جاهز» بمدة فعلية ← يرسل للمراجعة (يصبح للقراءة فقط) ← المالك يعتمد بسعر 3.500 وينشر ← الطالب يجد المعلم ← يشاهد **المعاينة المجانية** (رابط تضمين موقّع مقبول) والدرس الثاني مقفل ← يشتري ويدفع ← يشاهد **الفيديوهات الثلاثة** ← **طالب آخر غير مشترٍ يُمنع** (لا يصدر له رابط، ورابط مزور يُرفض 403) ← السجل المحاسبي: إجمالي 3500 / صافي 3500 / حصة المعلم 1400 / المنصة 2100 ← يظهر البيع في صفحة المعلم لدى المالك وفي التقارير وفي «أرباحي» لدى المعلم، دون كشف بيانات الطالب للمعلم.

**الرفع نيابة عن معلم بدون حساب** — نفس الملف ✅: معلم بوضع «يديره المالك» (بلا مستخدم) ← المالك ينشئ «مراجعة اختبار قصير» باسمه ويرفع الفيديو ← النشر يُسمح فقط بعد اكتمال المعالجة ← `uploaded_by` = المالك ← يظهر للطلاب باسم المعلم وفي صفحته.

تغطية التكامل الإضافية (Vitest): الاحتواء المتداخل حتى 4 مستويات ومنع الحلقات، فترات الإتاحة والانتهاء وإعادة الشراء، دقة توزيع الخصم والرسوم على الفلس، عدم تكرار الأرباح عند التأكيد المتزامن، عكسها عند الاسترداد، الرصيد بعد التسويات، لقطة اسم المعلم، عزل صلاحيات المعلمين، حالات وصول الدروس (غير جاهز/مجاني/مملوك/ممنوع)، رفع TUS حقيقي بـ tus-js-client، توقيع Webhook و Embed، حد الدخول لكل IP يحتسب المحاولات الفاشلة فقط (شبكات المدارس).

**أخطاء اكتُشفت وأُصلحت في هذه المرحلة:** حد عمق الحاويات لا يحتسب موقع الحاوية (ترحيل 0003)، حد الدخول لكل IP كان يحتسب الدخول الناجح، `upgrade-insecure-requests` كان يُفعَّل على خوادم غير HTTPS، كلمة مرور المعلم المؤقتة تختفي بعد الإنشاء، صفحات المالك كانت ترجع 200 بدل 404 للمعلم (بدون تسريب بيانات)، الفيديو مخفي في قواعد بيانات حفظت الإعداد القديم (ترحيل 0004).

## اختبارات أمنية إضافية مغطاة

- توقيع Webhook خاطئ أو بيانات معدلة ← 401 بدون أي تغيير.
- Webhook مزور بحالة PAID لفاتورة غير مدفوعة ← لا منح (إعادة الاستعلام من البوابة).
- فاتورة ليست لنا، أو مبلغ لا يطابق، أو فاتورة طلب آخر، أو بيئة دفع مختلفة ← رفض.
- وضع الإنتاج لا يعمل دون مفتاح + مفتاح Webhook + تأكيد صريح، ويُرفض إن كان الرابط تجريبيًا.
- رفع ملف بنوع مزيف (يُتحقق من التوقيع الثنائي) أو بحجم زائد أو برمز رفع معدل أو لمسار منتج آخر ← رفض.
- محاولات Path Traversal في مفاتيح التخزين، وروابط إعادة توجيه خارجية (Open Redirect)، وكوكي سلة مشوّه.
- الطالب لا يصل إلى `/admin` (404) ولا إلى واجهات الرفع.
- تحديد محاولات الدخول (قفل بعد 5 محاولات خاطئة) واستخدام رابط الاستعادة مرة واحدة فقط.

## حالة الوظائف

### ✅ مكتمل ومختبر

- الهيكل الدراسي: المرحلة المتوسطة (الصفوف 6–9) بموادها الست، مع المرحلتين الابتدائية والثانوية مخفيتين وقابلتين للتفعيل من لوحة الإدارة. لا تظهر أقسام فارغة للطالب.
- الصفحات العامة: الرئيسية، المرحلة، الصف، المادة (تصفية حسب الفصل)، المنتج، الباقات، الشروط، الخصوصية، الاسترجاع، التواصل، 404.
- السلة (للزائر أيضًا)، الكوبونات (نسبة/مبلغ، تاريخ، حد أدنى، حد لكل مستخدم، حد إجمالي)، الطلب المجاني عند خصم 100%.
- الدفع عبر MyFatoorah v2 ضد محاكي مطابق للعقد: InitiatePayment، ExecutePayment، SendPayment، GetPaymentStatus، Webhook V2، إعادة محاولة الدفع، تحديث حالة طلب معلّق.
- المكتبة (تجميع حسب الصف والمادة، تصفية حسب النوع، «أكمل من حيث توقفت»).
- قارئ PDF المدمج (عرض الصفحات عند الحاجة، تكبير/تصغير، رقم الصفحة، حفظ التقدم، علامة مائية على الخادم وفي القارئ، تنزيل فقط للمسموح).
- الحسابات: تسجيل، دخول، خروج، استعادة كلمة المرور، تغيير كلمة المرور، تعديل البيانات، الطلبات والفواتير.
- لوحة الإدارة: الإحصاءات (بيانات حقيقية فقط مع استبعاد الطلبات التجريبية)، المنتجات (إنشاء، رفع متعدد بمؤشر تقدم، غلاف، معاينة تلقائية/مخصصة، نشر/إخفاء/أرشفة/حذف، تعديل السعر، الترتيب)، الباقات، المراحل والمواد، الطلبات (استرداد يسحب صلاحيات الطلب فقط)، الطلاب (منح/سحب يدوي بسبب إلزامي + سجل تدقيق، إيقاف الحساب)، الكوبونات، التقارير وتصدير CSV، الإعدادات (الاسم، الشعار، الألوان، التواصل، الأسئلة الشائعة، العام الدراسي، العلامة المائية، الفيديو). *(تم التحقق من لوحة الإدارة بسكربتات Playwright أثناء البناء، والرحلة الحاسمة باختبار E2E آلي.)*
- SEO: Metadata، Open Graph، canonical، JSON-LD للمنتجات، `sitemap.xml`، `robots.txt`، `noindex` للمسارات الخاصة.
- الأمان: CSP بـ nonce، رؤوس الأمان، RLS على كل الجداول، تحقق Zod على الخادم.

### 🔑 يحتاج إعدادًا أو مفاتيح من مالك المنصة

- مفتاح MyFatoorah التجريبي ثم الإنتاجي، ومفتاح توقيع Webhook V2، وتفعيل كي نت/البطاقات/Apple Pay في حساب التاجر، وضبط رابط Webhook.
- مشروع Supabase (رابط قاعدة البيانات، مفتاح service_role) وتشغيل `supabase/storage-buckets.sql`.
- خادم SMTP لرسائل استعادة كلمة المرور (`MAIL_DRIVER=smtp`).
- الدومين وإعدادات DNS في Vercel، و`APP_URL` النهائي.
- إنشاء حساب المدير الأول عبر `npm run admin:create`.
- إدخال الاسم النهائي والشعار والألوان وبيانات التواصل ورقم واتساب من «إعدادات المنصة».
- رفع المحتوى الحقيقي (المذكرات والأسعار) — البيانات التجريبية لا تُنشر تلقائيًا.
